# I18n

Translations with MessageFormat 2 messages, and numbers, dates and plurals formatted for the user's locale.
`I18nService` wraps [dXn.I18n](https://github.com/dXnSix/dXn.I18n)'s `Translator` (messages, bundles, fallback lookup)
and formats with [dXn.Intl](https://github.com/dXnSix/dXn.Intl) (ICU4X), the same on every platform.

## Register

```rust
builder.add_i18n(|options| {
    options.default_language("en").fallback_language("de");
})
```

`add_i18n` registers the [asset service](assets.md) too. `I18nService` is a startup service that initializes after it.

## Configure

Options bind from `RayX:Services:I18N`, then the closure changes them: the default language, the fallback languages,
the resources path (`locales`), the default namespace, automatic loading of the asset catalog's translations, following
the platform's languages, the missing-message policy and bidi isolation.

```json
{ "RayX": { "Services": { "I18N": { "defaultLanguage": "en", "fallbackLanguages": ["de"] } } } }
```

## Translations

Translations are assets: `locales/<language>.json`, or `locales/<language>/<namespace>.json`, whose ids a namespace
other than the default one prefixes (`checkout.title`). Every language loads at startup, so changing the language is
immediate.

Every package the [asset service](assets.md) reads can ship translations. A message several of them have comes from
the package listed first in the asset options, the app's own, so an app overrides the text of the libraries it uses;
the messages only a library has still come from it.

## Use

```rust
let i18n = services.required_service::<I18nService>()?;
let title = i18n.t("title");
let cart = i18n.format("cart", &Args::new().with("n", 3)); // "3 items"
i18n.set_language("de")?;
```

- The language follows the platform service's preferred languages and clock (the best of the app's languages for the
  user's list, with the user's region and `-u-hc-` hour cycle) until the app picks one with `set_language`.
- Messages are looked up through the language's parents, the fallback languages and the default one.
- `locale()`, `language()`, `available_languages()`, `direction()`, `plural_category(n)`; `subscribe` hears every
  change of language, time zone or messages.

## Time zones

Instants are shown in the user's time zone: `time_zone()` is the platform's (an IANA name such as `Europe/Zagreb`),
else UTC, until the app sets one with `set_time_zone`. `local_time(instant)` takes an RFC 3339 instant with its offset
(`2026-11-02T09:30:00Z`) and `local_time_from_millis(millis)` milliseconds after the Unix epoch; each gives the wall
time there, to format with `format_date_time` or pass as a message's date. The zones come from dXn.Intl's `tz` feature
and the IANA database it bundles.

## TSX

```tsx
const i18n = I18n.of(app);
i18n.t("cart", { n: 3 });
i18n.t("sent", { at: date.toISOString() }); // a date in the user's time zone
i18n.formatDate(date.toISOString(), { length: "long", time: "minute" });
i18n.formatNumber(0.25, { style: "percent" });
i18n.setLanguage("de");
i18n.onChange((locale) => refresh());
```

- `t` takes text, numbers, booleans and instants (`date.toISOString()`, a timestamp with its offset). A `Date` or any
  other object throws, because JavaScript hands it over as an empty object.
- `formatDate(instant, { length, date, time, hourCycle })`: `length` is `"short"`, `"medium"` (the default) or
  `"long"`; `date: false` leaves the date out; `time` (`"hour"`, `"minute"` or `"second"`) adds the time of day;
  `hourCycle` (`"h11"`, `"h12"`, `"h23"`, `"h24"`) overrides the locale's clock.
- `formatNumber(value, { style, currency, minimumIntegerDigits, minimumFractionDigits, maximumFractionDigits,
  useGrouping })`: `style` is `"decimal"` (the default), `"percent"` or `"currency"` with an ISO 4217 `currency`.
- `timeZone()` is the zone instants are shown in; `onChange` hears changes of the locale, the time zone and the
  messages.
